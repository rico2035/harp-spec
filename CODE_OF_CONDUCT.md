# Code of Conduct

HARP is an open standard built in public. The work depends on people being able to disagree on technical merits without the conversation turning personal. This Code of Conduct applies to issues, RFCs, pull requests, and any HARP-run discussion space.

## Our standard

- Focus on the spec, the schemas, the implementations, and the evidence. Argue the design, not the person.
- Assume good faith. Most disagreements are about requirements you each see from a different seat.
- Be specific. "This breaks backward compatibility for a generic auth.md agent because X" moves the work forward. "This is bad" does not.
- Respect the open process. Decisions and their rationale are recorded in the repository so the record is reviewable later.

## Unacceptable behavior

Harassment, personal attacks, discriminatory language, sustained disruption of discussion, and publishing others' private information. Sharing real protected health information (PHI) in any issue, RFC, example, or test case is never acceptable. Use synthetic data only.

## Reporting

Report conduct concerns privately to conduct@goneomics.com. Reports are handled discreetly. Do not raise PHI exposure or security issues in a public issue. Email security@goneomics.com for those.

## Enforcement

Maintainers (see `MAINTAINERS.md`) are responsible for clarifying and enforcing this standard. Responses range from a request to edit a comment, to a temporary block from a discussion, to removal from the project for repeated or severe violations. Maintainers who do not follow the Code of Conduct in good faith may face consequences decided by the other maintainers.

This Code of Conduct adapts the spirit of the Contributor Covenant for a standards project that handles regulated healthcare workflows.
